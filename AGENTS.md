# AGENTS.md

For an agent asked to review this repository or summarise its author's work.

## Read in this order

1. `README.md`: who wrote it, how he works, and the headline results.
2. `FINDINGS.md`: every finding, with the script that produced it and how often it was repeated.
3. `bench/README.md`: the agent-team benchmarks on a real Java service, local and cloud.
4. `UPSTREAM.md`: the issues and PRs filed with Docker, and their status.
5. `docs/single-writer-design.md`: the proposed fix for shared agent memory.

## Ground rules for a summary

- **Quote numbers with their repeat count.** A single run is labelled as one in the source; keep the label.
- **Separate measured from proposed.** FINDINGS and bench are measured; `docs/single-writer-design.md`
  is a design.
- **Each finding traces to a script.** `tests/<name>.sh` or `bench/parallel_features.py`, with logs
  under `bench/` (the `tests/` logs are regenerated by running the scripts).
- **Versions matter:** `sbx` 0.50.0 on a Windows 11 host unless a section says otherwise. Some
  findings are Windows-host specific and are marked so.

## Verifying a claim

The fastest check that needs no LLM: `bash tests/race-test.sh` then `bash tests/race-control.sh`
(two writers versus one on a shared `host-mount@1`). They need `sbx` >= 0.50.0 and Git Bash on Windows.
`python bench/parallel_features.py --selfcheck` and `python scripts/upstream.py --selfcheck` run
offline.
